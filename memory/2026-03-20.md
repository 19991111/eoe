## Bug分析: 繁殖节点添加问题

### 问题描述
繁殖时子代的 `state.node_counts` 与实际基因组节点数不同步

### 根因分析

**Bug #1: 计数器无条件增加**
```python
# batched_agents.py 第2117行
add_mask = torch.rand(n_spawn, device=self.device) < add_node_prob  # 30%概率
self.state.node_counts[child_indices] += add_mask.long()  # 无条件+1!
```

但 `mutate_add_node()` 可能失败:
```python
# genome.py 第621行 - mutate_add_node() 内部
enabled_edges = [e for e in self.edges if e['enabled']]
if not enabled_edges:
    return False  # 没有可分裂的边时返回False
```

**结果**: 计数器+1，但实际没加节点 → 不同步

**Bug #2: node_counts_tensor 未更新**
```python
# set_brains() 中正确设置了
self.node_counts_tensor[idx] = len(nodes)  # 第2477行

# 但 _process_reproduction() 中没有更新!
# 子代创建后 node_counts_tensor 没有同步
```

### 修复方案

**方案A (推荐)**: 计数器条件增加
```python
# 第2142行改为:
if add_mask[i].item():
    if child_genome.mutate_add_node(output_weight=1.0):
        self.state.node_counts[child_indices[i]] += 1  # 成功才+1
```

**方案B**: 添加失败回滚
```python
if add_mask[i].item():
    success = child_genome.mutate_add_node(output_weight=1.0)
    if not success:
        self.state.node_counts[child_indices[i]] -= 1  # 失败则撤销
```

**方案C**: 同步 node_counts_tensor
```python
# 在第2158行后添加:
self.node_counts_tensor[child_idx] = len(child_genome.nodes)
```

### 修复优先级
- P0: Bug #1 计数器同步问题
- P1: Bug #2 node_counts_tensor 同步

## 🔬 基准测试关键发现

### 机制验证成功
- ✅ Reward调制Hebbian: 代码正确实现
- ✅ 探索噪声: 正确注入
- ✅ 蒙特梭利环境: 正确创建

### 发现系统性问题: 前馈断层 (Feedforward Disconnect)

**问题**: 演化保存的拓扑结构 + 默认brain都存在sensor到actuator的连接断裂

**证据**:
```
默认Brain结构: SENSOR -> PREDICTOR -> ACTUATOR
              (PREDICTOR激活=0导致链路断开)
v15保存结构: 同样存在类似问题
```

**根因**: 旧演化环境没有后天学习机制，演化出"看似复杂但实际断路"的畸形结构

**解决方案**: 
1. 用默认brain跑通Level 1-3建立基线（证明学习机制无Bug）
2. 开启"一生学习(Hebbian)+拓扑变异"的全新演化
3. 寻找"可学习性(Learnability)"强的拓扑结构
